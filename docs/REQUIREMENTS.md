# mercilint 要件

## 背景・目的
コードを容赦なく煽る(roast)が、全ツッコミが実際の修正提案に対応しているClaude Codeレビュースキル。純ネタでは伸びず、実用一辺倒では面白くない — 「ネタの皮を被った実用スキル」で英語圏スキル市場の勝ちパターン(方法論の蒸留＋映えるREADME)を狙う。詳細は docs/IDEA.md を参照。

**成功条件**: `/roast` で作業中のdiffに対して「笑えるが全部的確」なレビューが返り、READMEを見た他人がインストールしたくなる状態。

## ユーザー
グローバルの開発者に公開(英語)。日本市場は狙わない。まずは自分で日常使いしてキャラと精度を磨く。

## スコープ

### やること(MVP)
- `/roast`: 作業中のdiff(未コミット変更)を毒舌レビューするスキル本体(SKILL.md)
- roast→修正の完全マッピング: 全ツッコミにseverity(致命/高/中/低)と具体的修正提案を必ず対応させる
- 単一の強い毒舌キャラの作り込み(ブレない声・口調ガイドラインをスキル内に蒸留)
- 映えるREADME(英語): デモ例、before/after、インストール手順

### やらないこと(今回は)
- CLI・VSCode拡張などのコード実装(Markdownのみで完結)
- 複数persona・辛口レベル調整(単一キャラを磨く)
- 日本語ローカライズ
- Web UI・SaaS化
- リポジトリ全体スキャン・ファイル指定はM2以降のオプション扱い

## 技術選定

| 項目 | 選定 | 理由 |
|------|------|------|
| スキル本体 | Markdown(SKILL.md) | ビルド・デプロイ不要、工数最小 |
| 対象プラットフォーム | Claude Code | スキル市場が今熱い。自分が日常使いできる |
| バックエンド | なし | 不要 |
| フロントエンド | なし | 不要 |
| インフラ | なし(GitHubのみ) | 配布はgit clone / スキルインストールで完結 |

## 公開・運用
- リポジトリ: まずprivate(kpab)、完成度が上がったらpublic化 / ライセンス: MIT(public化時に付与)
- デプロイ先: なし(GitHubからのインストールのみ)
- CI: なし
- 名前: `mercilint`(GitHub全体で0件、検索独占可能)。コマンドは `/roast`。descriptionに "roast" "brutal code review" 等の検索キーワードを盛る

## マイルストーン

- **M1(最小の動くもの)**: `/roast` が自分の環境で動き、実際のdiffに対して毒舌＋severity＋修正提案のセットを返す
  - [x] キャラの具体像を決める → 辛辣シェフ(Ramsay風厨房の暴君)。roast=料理用語のブランド一貫性とミーム認知が根拠
  - [x] roast一件ごとの出力テンプレートを確定する → severity(RAW/BURNT/BLAND/GARNISH) + burn + fix
  - [x] SKILL.md本体を書き上げる(diff取得→レビュー→出力の手順、diffが空のときの振る舞い含む)
  - [x] `~/.claude/skills/roast` にリンクし、実際のdiffで検証 → 欠陥入りdiffでドライラン済み、出力は仕様どおり(SKILL.md調整不要)。実セッションでの発火確認は日常使い(M2)で継続
- **M2**: キャラ磨き込み＋英語README(デモ例つき)完成。数日間の日常使いでroastの精度・面白さを検証
- **M3**: public化(MIT付与)、初動の見せ方(Show HN / X投稿等)を実行
